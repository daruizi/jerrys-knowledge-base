01

认识 Codex：它到底是什么？

先分清三个同名概念，再看它的四种产品形态。

一句话理解

Codex 是 OpenAI 的"智能体编程"产品线。它不只聊天，而是真正动手干活：读代码、改文件、跑命令、看报错、修 bug、提交 Git——直到目标达成。可以理解为：ChatGPT 的大脑 + 一双手（终端 / 文件 / 浏览器 / 桌面操控）+ 一套安全围栏（沙箱）。

别混淆：历史上有三个"Codex"

时期名称是什么现状
2021–2023Codex（模型）GPT-3 的代码微调模型，GitHub Copilot 的引擎API 已停用
2025–Codex（云端智能体）ChatGPT 内的软件工程 Agent，云端沙箱虚拟机执行现役
2025–Codex CLI / App开源本地终端智能体 + 桌面应用现役 · 本文主角

产品家族：四种形态，一个订阅

macOS / Windows 原生应用，新手首选。多线程并行管理任务，内置技能市集、插件系统、可视化预览和自动化（定时任务 / 监控器）。本文大部分截图级体验都来自它。

适合：想要图形界面、需要同时推进多个任务的人。

终端里的 codex 命令，开源（Apache 2.0）。可脚本化、可 SSH 到服务器直接用、可自定义模型提供商接国产模型——这是它最不可替代的价值。

适合：命令行重度用户、运维、国内网络环境用户。

VS Code / Cursor 侧边栏面板。选中代码直接提问或下达任务，改动以 diff 形式呈现，不离开编辑器。

适合：边写边问、局部重构场景。

ChatGPT 网页 / 手机 App 内的 Codex 标签。连接 GitHub 仓库，在云端独立虚拟机里并行跑任务，干完直接开 PR。下班前丢个任务，地铁上用手机看进度。

适合：异步长任务、移动办公。

生态优势

四种形态共享同一个 ChatGPT 订阅额度，上下文与技能（Skills）可打通——这是 Codex 相对其他工具最大的差异化。

核心能力全景

从工作循环到 Computer Use，一张图看懂 Codex 能干什么。

智能体工作循环

普通聊天机器人是"一问一答"，Codex 是"接到目标 → 自主闭环"：理解 → 计划 → 调用工具（读文件 / 跑命令 / 搜索 / 看图）→ 观察结果 → 未达成就继续循环 → 达成后汇报并提交。

沙箱 × 审批，双旋钮安全模型

沙箱三档：read-only → workspace-write → danger-full-access；审批四档：untrusted → on-failure → on-request → never。macOS 用 seatbelt，Windows 有原生沙箱。新手推荐 workspace-write + on-failure。

06

配置精通：从 config.toml 到自定义模型

本章基于作者本机的真实配置——一种高阶但典型的用法：用 Codex 的壳，跑国产大模型。

配置文件在哪里

~/.codex/ # Windows: C:\Users\你的用户名\.codex\ ├── config.toml # 全局配置中枢 ├── model-catalog.local.json # 自定义模型清单（路径在 config 里声明） ├── AGENTS.md # 全局规范（可选） └── skills/ # 技能库，每个技能一个文件夹 └── my-skill/SKILL.md

真实 config.toml 逐行解读

~/.codex/config.toml
# ===== 模型三件套 =====
model_provider = "Model_Studio_Token_Plan"   # 用哪个提供商（对应下方 [model_providers.X]）
model = "qwen3.8-max-preview"                # 默认模型
model_reasoning_effort = "xhigh"             # 推理深度：low/medium/high/xhigh/max

# ===== 自定义模型目录 =====
model_catalog_json = "~/.codex/model-catalog.local.json"
# ⚠ 必须是"文件路径"（用正斜杠），不能把 JSON 内联写在这里

# ===== 安全两旋钮 =====
sandbox_mode = "danger-full-access"          # read-only / workspace-write / danger-full-access
approval_policy = "never"                    # untrusted / on-failure / on-request / never

# ===== 自定义提供商：阿里云百炼 Token Plan =====
[model_providers.Model_Studio_Token_Plan]
name = "Model_Studio_Token_Plan"
base_url = "https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1"
env_key = "OPENAI_API_KEY"                   # 从哪个环境变量读 API Key
wire_api = "responses"                       # ⚠ 只能填 responses（chat 模式已废弃）

# ===== 桌面应用偏好 =====
[desktop]
followUpQueueMode = "queue"                  # 多条追问自动排队，不打断当前任务
localeOverride = "zh-CN"                     # 界面语言

# ===== 项目信任 =====
[projects.'c:\users\jingrui']
trust_level = "trusted"                      # 受信项目不弹信任确认

# ===== 插件开关 =====
[plugins."pdf@openai-primary-runtime"]
enabled = true
[plugins."spreadsheets@openai-primary-runtime"]
enabled = true
三个最关键的字段

model_reasoning_effort 是最直接的"油门"：简单任务 low/medium 省钱，疑难 debug 用 high/xhigh。wire_api 只能填 responses——第三方提供商不支持它就接不上，这是最常见的坑。env_key 让密钥走环境变量，不落在配置文件里。

model-catalog.local.json（节选）
{
  "models": [
    {
      "slug": "qwen3.8-max-preview",
      "display_name": "qwen3.8-max-preview",
      "description": "Qwen3.8 flagship preview model...",
      "default_reasoning_level": "medium",
      "supported_reasoning_levels": [
        { "effort": "low" }, { "effort": "medium" },
        { "effort": "high" }, { "effort": "xhigh" }
      ],
      "base_instructions": "You are Codex, a coding agent...",
      "supports_reasoning_summaries": true,
      "context_window": 272000,
      "input_modalities": ["text", "image"],
      "support_verbosity": false          // 非 OpenAI 模型填 false
    }
  ]
}
字段必填说明
slug✓模型唯一标识，model = "..." 填的就是它
display_name✓界面显示名
base_instructions✓系统提示词基底
supports_reasoning_summaries✓是否支持推理摘要
support_verbosity✓是否支持 verbosity 参数（非 OpenAI 模型填 false）
supported_reasoning_levels建议该模型支持的推理档位
context_window建议上下文窗口大小
input_modalities建议支持的输入模态（text / image）
升级后报 "missing field X"？

Codex 升级可能新增必填字段（support_verbosity 就是某次更新后突然要求的）。报错即目录 schema 落后，对照补字段即可。

AGENTS.md 编写指南

AGENTS.md（真实文件精简版）
# 工作区规范

## 环境
- OS: Windows 11，PowerShell（受限语言模式）
- Python: C:/Users/xxx/.../python.exe

## 关键规则
1. PowerShell 里不要用 .NET 方法调用，复杂操作写 Python 脚本
2. 中文/emoji 内容不要 print 到控制台（GBK 会乱码），写 UTF-8 文件
3. 处理 .xlsx 用 openpyxl，pandas 未安装
4. TOML 里的 Windows 路径用正斜杠
  • 写"它不可能知道的事"：本机特殊路径、私有工具、团队黑话。
  • 写"它总是犯的错"：把每次纠正它的话沉淀下来。
  • 短句子 + 编号列表，别写散文；项目级放项目根目录，通用放 ~/.codex/AGENTS.md。

07

进阶实战：多 Agent、自动化与工程化

从"能用"到"好用"，差的都是工程纪律。

多 Agent 并行开发

桌面应用里，主 Agent 可以派出多个子 Agent 并行工作。用好的三个原则：

  • 写集分离：给每个子 Agent 分配互不重叠的文件修改范围（一个改前端、一个改后端、一个跑测试）。
  • 阻塞任务自己做：下一步马上要用的结果，主 Agent 亲自干；能并行的"侧翼任务"才分出去。
  • 回来要验收：子 Agent 交付后快速审查 diff，再整合。

自动化（Automations）

桌面应用原生支持定时任务、网页/文件监控、跟进汇报与线程唤醒。用法就是自然语言：

"帮我建一个自动化，每周一早上把上周的账单文件夹汇总成表格。"

Git Worktree 隔离开发

SHELL
git worktree add ../proj-feature-a feature-a
git worktree add ../proj-feature-b feature-b

并行任务最怕互相踩文件。给每个任务开独立 worktree，让不同线程/子 Agent 各自负责，互不干扰，最后合并。

大型项目最佳实践清单

  • 先规划后动手：复杂任务先说"只列计划，不要改代码"，确认后再执行。
  • 小步提交：每完成一个可验证的阶段就 commit，/undo 和 git revert 是后悔药。
  • 测试先行：先写失败的测试，再写实现（TDD），交付质量显著提升。
  • 上下文管理：会话变长就 /compact；换任务就 /clear 或开新线程。
  • 让它自查：收尾前说"运行全部验证命令，确认通过后再告诉我完成"。
  • 经验沉淀：每次纠正后把教训写进 AGENTS.md——AI 不会两次掉进同一条河。

Windows 踩坑实录（血泪经验）

全部来自真实使用记录，Windows 用户建议通读。

PIT 01 PowerShell 受限语言模式（Constrained Language Mode）
症状：.NET 方法调用报错；ForEach-Object 里调方法失败；正则 [^...] 被错误解析。
对策：复杂逻辑一律写成 .py 文件再执行，或用 here-string 管道 @'...'@ | python -；别用 python -c "多行复杂字符串"。
PIT 02 中文乱码（GBK 之痛）
症状：python -c 打印中文变乱码；GitHub API 返回带 emoji 直接抛 gbk codec can't encode character。
对策：中文/emoji 内容永远写进 UTF-8 文件，再 Get-Content -Encoding UTF8 读取；不要依赖控制台 stdout 验证中文。
PIT 03 更新 Codex 报 EBUSY
症状：npm update -g @openai/codex 提示文件占用。
对策：Codex 运行时无法自我更新。完全退出 Codex，另开普通终端执行更新，再重启。
PIT 04 TOML 里的 Windows 路径
症状：配置解析失败或路径找不到。
对策：config.toml 里一律用正斜杠 C:/Users/...；model_catalog_json 必须是文件路径，不能内联 JSON。
PIT 05 模型目录 schema 随版本变化
症状：升级后报 "Windows setup didn't finish" + "missing field X"。
对策：目录缺了新必填字段（如 support_verbosity）。对照报错补字段，非 OpenAI 模型填 false。

Codex 是 ChatGPT 生态里的"智能体编程"产品线。订阅 ChatGPT Plus/Pro 即可使用；桌面应用与 ChatGPT 桌面版正在融合为统一入口（2026 年 7 月的 ChatGPT Work 更新）。

Free 套餐有基础额度可以体验；认真用的话 Plus（$20/月）起步，Pro（$100/月约 5 倍额度、$200/月约 20 倍额度）适合重度开发。

两条路：① CLI + 自定义提供商接阿里云百炼等国产模型（第六章），完全合规、无需梯子；② 云端 Codex 和官方订阅需要能访问 OpenAI 的网络条件与支付方式。

简单任务切 flash/plus 档模型、推理深度调 low/medium；长会话勤用 /compact，换任务就 /clear；写好 AGENTS.md 减少反复解释；大任务拆成多个小线程，避免超长上下文拖到底。

本地 CLI/App 的任务在你的机器沙箱里执行，代码片段发送给模型用于推理。Business/Enterprise 套餐明确数据不用于训练；个人套餐以 OpenAI 官方条款为准，敏感项目建议私有化方案或国产模型提供商。
