## 1. 什么是 /loop

`/loop` 是 Claude Code 内置的一个 **skill（技能/斜杠命令）**，它允许你设定一个 prompt 或 slash 命令，让 Claude Code **按指定的时间间隔反复执行**。

与系统级的 cron 不同，`/loop` 的每次迭代都会让 Claude **完整思考和分析**，而不仅仅是机械地执行命令。这意味着 Claude 可以：

- 解读命令输出，判断是否正常
- 根据当前状态决定下一步操作
- 向你汇报有意义的摘要，而非原始日志
- 在满足条件时自动停止

**核心价值**：把 Claude 变成一个"有智慧的值班员"，而不只是一个定时器。

## 2. 基本语法

```
/loop <间隔> <prompt 或 slash 命令>
```

| 参数 | 说明 | 示例 |
|------|------|------|
| `<间隔>` | 执行间隔，支持 `s`（秒）、`m`（分）、`h`（时） | `5m`、`30s`、`1h` |
| `<prompt>` | 要让 Claude 反复执行的提示词或命令 | `"检查部署状态"` |

**示例**：

```
/loop 5m 检查 CI/CD 部署状态，如果完成告诉我结果
/loop 10m /code-review
/loop 30s 运行 python test.py，如果失败就修复并重试
```

> **注意**：如果不指定间隔，某些模式下默认间隔为 `10m`。

## 3. 两种运行模式

### 3.1 固定间隔模式

用户显式指定时间间隔，Claude 每隔该时间执行一次。

```
/loop 5m 检查服务器健康状态
```

**特点**：
- 间隔固定，行为可预测
- 适合已知合理轮询频率的场景
- 每次执行都会消耗 token

### 3.2 动态自适应模式（Dynamic Pacing）

当使用 `/loop` 不带固定间隔时（即用户说"帮我持续盯着这个任务"而不指定具体间隔），Claude 进入**动态自适应模式**。

在这种模式下，Claude 会根据任务的性质**自行决定**合适的检查频率：

- 任务刚开始 → 频繁检查
- 任务进入稳定等待期 → 降低检查频率
- 检测到异常信号 → 恢复高频检查

**特点**：
- 无需手动指定间隔
- Claude 自主判断节奏
- 更省 token，更智能

## 4. 核心机制

`/loop` 底层依赖两个关键工具：

### CronCreate — 定时调度

```
CronCreate({
  cron: "*/5 * * * *",      // 标准 5 字段 cron 表达式
  prompt: "检查部署状态",     // 每次触发时执行的 prompt
  recurring: true,           // true = 循环执行，false = 一次性
  durable: false             // true = 持久化到磁盘，重启后恢复
})
```

**关键特性**：
- 使用用户本地时区的标准 5 字段 cron 语法
- 非持久任务（`durable: false`）仅在当前会话有效
- 持久任务（`durable: true`）写入 `.claude/scheduled_tasks.json`
- 循环任务最长自动存活 **7 天**，到期后最后触发一次并删除

### ScheduleWakeup — 动态唤醒

用于动态自适应模式，Claude 自行决定何时唤醒自己：

```
ScheduleWakeup({
  delaySeconds: 270,           // 多少秒后唤醒
  prompt: "继续检查部署状态",   // 唤醒时执行的 prompt
  reason: "等待 CI 构建完成"   // 告知用户为什么选择这个间隔
})
```

**缓存优化策略**：
- Anthropic 的 prompt cache 有 5 分钟 TTL
- 间隔 < 5 分钟（60s–270s）→ cache 命中，省 token
- 间隔 5 分钟–1 小时（300s–3600s）→ cache 失效，但适合等待型任务
- Claude 会自动选择最优间隔，避免无意义的 cache miss

## 5. 典型使用场景与案例

### 5.1 轮询部署状态

**场景**：你刚触发了一个部署，需要持续监控直到完成。

```
/loop 5m 检查 CI/CD 部署状态。运行 `gh run list --limit 1` 查看最新 workflow run 的状态。
如果状态是 success，告诉我"部署成功"并停止轮询。
如果状态是 failure，告诉我失败原因。
如果还在进行中，简要告知进度。
```

**为什么用 /loop 而不是 bash while 循环**：Claude 每次会**解读**输出，判断是否成功，而不是让你自己看原始日志。

### 5.2 看护长时间运行的任务

**场景**：后台有一个训练任务或数据处理任务，你需要知道它是否正常。

```
/loop 15m 检查后台训练任务的状态：
1. 运行 `ps aux | grep train.py` 确认进程是否存活
2. 检查 `tail -20 training.log` 看最近的日志
3. 如果有 ERROR 或异常，立即告诉我
4. 如果一切正常，简要汇报当前进度
```

### 5.3 周期性代码审查

**场景**：团队成员在持续提交代码，你想定期获取审查摘要。

```
/loop 30m 运行 /code-review，总结最近 30 分钟内的代码变更，重点关注潜在 bug 和安全问题。
```

### 5.4 监控日志与告警

**场景**：监控应用日志，发现异常及时告警。

```
/loop 2m 检查 /var/log/app/error.log 的最新内容。
如果发现新的错误条目：
- 分析错误原因
- 评估严重程度（低/中/高）
- 给出修复建议
如果没有新错误，回复"无异常"即可。
```

### 5.5 重复执行 slash 命令

**场景**：你想让某个 slash 命令定期运行。

```
/loop 1h /verify
```

这会让 Claude 每小时执行一次 `/verify` 命令来验证应用状态。

## 6. 与系统 Cron / Task Scheduler 的对比

| 特性 | `/loop` | 系统 Cron / Task Scheduler |
|------|---------|---------------------------|
| **执行方式** | Claude 思考后执行 | 直接执行命令 |
| **智能分析** | ✅ 每次迭代都有 AI 分析 | ❌ 纯机械执行 |
| **Token 消耗** | 每次消耗 token | 免费 |
| **依赖会话** | Claude Code 关闭则停止 | 系统级，独立运行 |
| **输出解读** | 自动解读并汇报 | 需要自己看日志 |
| **条件判断** | Claude 自主判断 | 需手动编写脚本逻辑 |
| **适合场景** | 需要"动脑"的监控 | 纯执行型定时任务 |
| **最短间隔** | 约 1 分钟 | 秒级（cron 最小为分钟） |
| **持久化** | 可选（durable: true） | 天然持久化 |

**选择建议**：

- 需要 Claude **理解、判断、汇报** → 用 `/loop`
- 只是**机械执行、记录日志** → 用系统 Cron / Task Scheduler

## 7. 限制与注意事项

### 7.1 Token 消耗

每次 `/loop` 触发都会调用 Claude，产生 token 消耗。如果间隔设置为 1 分钟，一天将触发 1440 次。

> **建议**：根据任务实际需要设置合理的间隔，避免过于频繁。

### 7.2 会话依赖

非持久模式（`durable: false`）下，关闭 Claude Code 会话后，定时任务就消失了。

### 7.3 7 天自动过期

循环任务（`recurring: true`）最长自动存活 **7 天**。7 天后会最后一次触发，然后自动删除。这是安全机制，防止遗忘的定时任务无限消耗。

### 7.4 非实时

`/loop` 的精度是分钟级，不适合秒级高频轮询。如果需要秒级监控，应使用专业监控工具。

### 7.5 不替代专业工具

`/loop` 是轻量级的智能轮询工具，不能替代：
- Prometheus / Grafana（专业监控）
- Jenkins / GitHub Actions（CI/CD 流水线）
- PagerDuty（专业告警）

## 8. 最佳实践

### 8.1 明确退出条件

每次使用 `/loop` 时，告诉 Claude 什么时候应该停止：

```
/loop 5m 检查部署状态。如果部署成功或失败（非进行中），告诉我结果后停止。
如果超过 30 分钟仍未完成，也停止并报告超时。
```

### 8.2 合理设置间隔

| 任务类型 | 建议间隔 | 原因 |
|---------|---------|------|
| CI/CD 部署监控 | 3–5 分钟 | 部署通常 5–15 分钟 |
| 后台任务看护 | 10–15 分钟 | 训练任务周期较长 |
| 日志监控 | 2–5 分钟 | 需要较快发现异常 |
| PR 审查 | 30 分钟–1 小时 | 代码变更不会太频繁 |

### 8.3 使用持久化模式保护长期任务

如果你设置的定时任务需要跨会话存活，使用 `durable: true`：

```
# Claude 会在内部使用 durable: true 将任务写入 .claude/scheduled_tasks.json
```

### 8.4 结合其他 slash 命令

`/loop` 可以嵌套调用其他 slash 命令：

```
/loop 1h /verify          # 每小时验证应用状态
/loop 30m /code-review    # 每半小时审查代码
/loop 15m /run            # 每 15 分钟运行并检查应用
```

### 8.5 注意 cache 成本优化

Claude 的 prompt cache 有 5 分钟 TTL。如果你设置的间隔是 3 分钟，cache 能命中，成本较低。如果间隔是 10 分钟，cache 会失效，每次都是全新推理。

> **技巧**：如果任务允许，将间隔设置为 5 分钟的因子（1m、2.5m、5m）可以最大化利用 cache。

## 9. 常见问题 FAQ

### Q: /loop 是官方内置命令吗？

是的，`/loop` 是 Claude Code 内置的 skill（技能），通过斜杠命令调用。

### Q: 如何停止一个正在运行的 /loop？

在 Claude Code 会话中，你可以直接告诉 Claude "停止 loop"，或者关闭当前会话。

### Q: /loop 会消耗多少 token？

取决于间隔和 prompt 复杂度。每次触发都相当于一次完整的 Claude 对话。建议根据实际需要设置合理间隔。

### Q: 可以同时运行多个 /loop 吗？

可以。每个 `/loop` 是独立的定时任务，互不干扰。

### Q: /loop 和 CronCreate 什么关系？

`/loop` 是用户面向的命令，底层使用 `CronCreate` 工具来注册定时任务。你也可以直接使用 `CronCreate` 获得更精细的控制（如指定 cron 表达式、设置持久化等）。

### Q: 重启 Claude Code 后 /loop 还在吗？

取决于是否设置了持久化（`durable: true`）。默认情况下（非持久化），关闭会话后任务消失。

### Q: 可以用 /loop 执行 Python 脚本吗？

可以，但不是最优选择。如果你的需求只是定时执行脚本（不需要 AI 分析），使用 Windows Task Scheduler 或 bash cron 更省资源。用 `/loop` 适合需要 Claude 解读脚本输出的场景。

### Q: 7 天自动过期是什么意思？

循环任务最长存活 7 天。这是安全机制，防止遗忘的任务无限消耗 token。到期前最后一次触发后自动删除。如果需要更长的周期，7 天后重新设置即可。
