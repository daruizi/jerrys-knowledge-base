Claude Code /loop 命令完全指南

从零开始，系统掌握 Claude Code 的 /loop 命令。本文涵盖语法、两种运行模式、底层机制、五大典型场景、与系统 Cron 的对比、限制与最佳实践。即使你从未使用过 /loop，也能轻松上手。

一句话总结：/loop 是 Claude Code 的"值班闹钟"——让 Claude 按固定间隔或自适应节奏，反复执行 prompt 或 slash 命令，适合需要 AI 智能参与的周期性监控与轮询任务。

什么是 /loop

/loop 是 Claude Code 内置的一个 skill（技能/斜杠命令），它允许你设定一个 prompt 或 slash 命令，让 Claude Code 按指定的时间间隔反复执行。

与系统级的 cron 不同，/loop 的每次迭代都会让 Claude 完整思考和分析，而不仅仅是机械地执行命令。这意味着 Claude 可以：

  • 解读命令输出，判断是否正常
  • 根据当前状态决定下一步操作
  • 汇报有意义的摘要，而非原始日志
  • 在满足条件时自动停止

基本语法

语法/loop <间隔> <prompt 或 slash 命令>
参数说明示例
<间隔>执行间隔，支持 s（秒）、m（分）、h（时）5m、30s、1h
<prompt>要让 Claude 反复执行的提示词或命令"检查部署状态"

示例

# 每 5 分钟检查部署状态
/loop 5m 检查 CI/CD 部署状态，如果完成告诉我结果

# 每 10 分钟执行代码审查
/loop 10m /code-review

# 每 30 秒运行测试并自动修复
/loop 30s 运行 python test.py，如果失败就修复并重试
注意：如果不指定间隔，在动态自适应模式下由 Claude 自行决定合适的检查频率。

两种运行模式

固定间隔模式

用户显式指定间隔

Claude 每隔固定时间执行一次 prompt。

  • 间隔固定，行为可预测
  • 适合已知合理轮询频率的场景
  • 每次执行都消耗 token
动态自适应模式

Claude 自主决定节奏

Claude 根据任务性质自行调整检查频率。

  • 无需手动指定间隔
  • 任务活跃时频繁，空闲时降频
  • 更省 token，更智能

固定间隔模式

# 每 5 分钟检查一次
/loop 5m 检查服务器健康状态

底层使用 CronCreate 注册一个标准 cron 表达式，按固定时间触发。

动态自适应模式（Dynamic Pacing）

当你说"帮我持续盯着这个任务"而不指定具体间隔时，Claude 进入动态自适应模式，通过 ScheduleWakeup 自行决定何时唤醒。

动态自适应节奏示意
启动期 等待期 异常 完成

核心机制

/loop 底层依赖两个关键工具：

CronCreate — 定时调度

APICronCreate({
  cron: "*/5 * * * *",       // 标准 5 字段 cron 表达式
  prompt: "检查部署状态",     // 每次触发时执行的 prompt
  recurring: true,           // true = 循环执行
  durable: false             // true = 持久化到磁盘
})
🕓

会话级（默认）

durable: false — 仅在当前 Claude Code 会话有效，关闭即消失。

💾

持久化

durable: true — 写入 .claude/scheduled_tasks.json，重启后恢复。

7 天自动过期：循环任务（recurring: true）最长自动存活 7 天。到期后最后一次触发，然后自动删除。这是安全机制，防止遗忘的任务无限消耗 token。

ScheduleWakeup — 动态唤醒

用于动态自适应模式，Claude 自行决定何时唤醒自己：

ScheduleWakeup({
  delaySeconds: 270,           // 多少秒后唤醒
  prompt: "继续检查部署状态",   // 唤醒时执行的 prompt
  reason: "等待 CI 构建完成"   // 告知用户为什么选这个间隔
})
缓存优化策略：Anthropic 的 prompt cache 有 5 分钟 TTL。间隔 < 5 分钟（60s–270s）可命中缓存，省 token。Claude 会自动选择最优间隔，避免无意义的 cache miss。

典型使用场景与案例

1
轮询部署状态

场景：你刚触发了一个部署，需要持续监控直到完成。

/loop 5m 检查 CI/CD 部署状态。运行 `gh run list --limit 1` 查看最新
workflow run 的状态。如果 success 告诉我"部署成功"并停止。
如果 failure 告诉我失败原因。还在进行中则简要告知进度。

为什么用 /loop 而不是 bash while 循环？Claude 每次会解读输出，判断是否成功，而不是让你自己看原始日志。

2
看护长时间运行的任务

场景：后台有训练任务或数据处理任务，你需要知道它是否正常。

/loop 15m 检查后台训练任务的状态：
1. 运行 `ps aux | grep train.py` 确认进程是否存活
2. 检查 `tail -20 training.log` 看最近的日志
3. 如果有 ERROR 或异常，立即告诉我
4. 如果一切正常，简要汇报当前进度
3
周期性代码审查

场景：团队成员在持续提交代码，你想定期获取审查摘要。

/loop 30m 运行 /code-review，总结最近 30 分钟内的代码变更，
重点关注潜在 bug 和安全问题。
4
监控日志与告警

场景：监控应用日志，发现异常及时告警。

/loop 2m 检查 /var/log/app/error.log 的最新内容。
如果发现新的错误条目：
- 分析错误原因
- 评估严重程度（低/中/高）
- 给出修复建议
如果没有新错误，回复"无异常"即可。
5
重复执行 slash 命令

场景：让某个 slash 命令定期运行。

/loop 1h /verify          # 每小时验证应用状态
/loop 30m /code-review    # 每半小时审查代码
/loop 15m /run            # 每 15 分钟运行并检查应用

限制与注意事项

💰

Token 消耗

每次触发都调用 Claude。间隔 1 分钟 = 一天 1440 次。请根据实际需要设置合理间隔。

🔌

会话依赖

默认非持久模式下，关闭 Claude Code 会话后定时任务消失。

⏰

7 天自动过期

循环任务最长存活 7 天，到期后最后一次触发并自动删除。需要更长的周期可重新设置。

📜

非实时

精度为分钟级，不适合秒级高频轮询。秒级监控应使用专业工具。

不替代专业工具：/loop 是轻量级智能轮询工具，不能替代 Prometheus/Grafana（监控）、Jenkins/GitHub Actions（CI/CD）、PagerDuty（告警）等专业系统。

最佳实践

8.1 明确退出条件

每次使用 /loop 时，告诉 Claude 什么时候应该停止：

/loop 5m 检查部署状态。如果成功或失败（非进行中），告诉我结果后停止。
如果超过 30 分钟仍未完成，也停止并报告超时。

8.2 合理设置间隔

任务类型建议间隔原因
CI/CD 部署监控3–5 分钟部署通常 5–15 分钟
后台任务看护10–15 分钟训练任务周期较长
日志监控2–5 分钟需要较快发现异常
PR 审查30 分钟–1 小时代码变更不会太频繁

8.3 利用 cache 优化成本

技巧：Claude 的 prompt cache 有 5 分钟 TTL。将间隔设置为 ≤5 分钟（如 1m、2.5m、5m）可命中缓存，成本显著降低。间隔 >5 分钟则每次都是全新推理。

8.4 结合其他 slash 命令

/loop 可以嵌套调用其他 slash 命令，形成自动化流水线：

/loop 1h /verify          # 每小时验证应用状态
/loop 30m /code-review    # 每半小时审查代码
/loop 15m /run            # 每 15 分钟运行并检查

常见问题 FAQ

Q: /loop 是官方内置命令吗？

是的，/loop 是 Claude Code 内置的 skill（技能），通过斜杠命令调用。

Q: 如何停止一个正在运行的 /loop？

在 Claude Code 会话中直接告诉 Claude "停止 loop"，或者关闭当前会话。也可以输入 cronlist 查看所有定时任务，然后用 CronDelete 删除指定任务。

Q: /loop 会消耗多少 token？

取决于间隔和 prompt 复杂度。每次触发都相当于一次完整的 Claude 对话。建议根据实际需要设置合理间隔。

Q: 可以同时运行多个 /loop 吗？

可以。每个 /loop 是独立的定时任务，互不干扰。

Q: /loop 和 CronCreate 什么关系？

/loop 是用户面向的命令，底层使用 CronCreate 工具注册定时任务。你也可以直接使用 CronCreate 获得更精细的控制（如指定 cron 表达式、设置持久化等）。

Q: 重启 Claude Code 后 /loop 还在吗？

取决于是否设置了持久化（durable: true）。默认情况下（非持久化），关闭会话后任务消失。

Q: 可以用 /loop 执行 Python 脚本吗？

可以，但不是最优选择。如果只需定时执行脚本（不需要 AI 分析），使用 Windows Task Scheduler 或系统 cron 更省资源。/loop 适合需要 Claude 解读脚本输出的场景。

Q: 7 天自动过期是什么意思？

循环任务最长存活 7 天。这是安全机制，防止遗忘的任务无限消耗 token。到期前最后一次触发后自动删除。需要更长周期，7 天后重新设置即可。
